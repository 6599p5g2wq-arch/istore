# iStore complete release package, 24 November 2026

This is the current complete PHP release package, with documented deployment requirements, not a guarantee of zero vulnerabilities or host certification. Read HOSTING-AR.md before production installation.

Included: storefront, cart/wishlist/checkout, customer profiles, variants, cities, coupons, verified reviews, loyalty/VIP/welcome offers, admin and separate control panel, login security/2FA/recovery/activity/idle handling, mobile bearer API, branding/favicon/logo, announcement/ticker controls, hero slider v6 (loop/reverse/swipe/dots/500ms text/fixed CTA), selected-order CSV, all earlier stock/input/installer corrections, and this security release.

Security changes: context escaping of PHP cart/wishlist/checkout HTML; image content and pixel validation; new raw SVG logo uploads disabled (PNG/JPG/WebP supported); existing images unchanged. Session-bound hidden form tokens; missing-Origin browser writes rejected; strict PHP sessions and login-ID rotation; cross-site logout protection and headers; public/mobile abuse limits and independent account/IP limits; atomic persistent counters; coupon row locking; input/rating/quantity checks; bounded password/body size; strict bearer syntax; bearer registration no longer opens a web login; SQL error details suppressed. Default admin/control passwords are rejected unless explicitly in development. Change starter values BEFORE production, or login will be blocked. No visual redesign.

Tracking web forms now POST phone privately. PHP mobile GET tracking remains compatible and rate-limited, but query phone remains a known privacy limitation requiring mobile client coordination. New SVG acceptance requires a safe rasterizer. Review existing raw SVG files separately.

Database: install.sql contains the complete current schema (32 tables), security/2FA, mobile, loyalty and rate-limit tables/columns, plus starter catalog (30 products, 4 brands, 26 cities). No customer orders, accounts, passwords, integration keys or production data. install.php is disabled by default via INSTALL_ENABLED=false, requires explicit temporary enable and POST/token, and refuses a populated settings database. Remove installer/SQL from the hosted root after setup. Never import starter data over a live database. Back up before upgrading. Existing PHP schema upgrades still run automatically and require DDL permissions; moving them to versioned one-off migrations remains a scaling follow-up.

Next companion release: Next 16.4.6 / React 19.3.1 / PostCSS 8.5.33, Node 22.x; private 15-minute receipt access and phone gate, customer-session revocation, approved toolbar wrap, same local security review fixes. Next public_rate_limits is a NEW SQLite table created automatically. Next is not bundled as PHP or executable on PHP-only hosting. Its code is on the separate main branch. PHP code is on php branch.

Verification: Next production build, zero known npm audit findings, 84 PHP syntax checks, local customer/order/price/stock/session/rate/upload/CSV/access regressions, four panel two-factor flows, recovery/replay/idle checks, concurrent coupon one-use test. Mobile products/tracking/login comparisons passed unchanged. Full fresh SQL import passed with 0 customers/0 orders. PHP has not been certified on your eventual host. SHA256SUMS.txt covers the included release files.

Still requires production work: durable DB/uploads and backups, correct HTTPS/proxy settings, host-specific deny/upload rules, supported runtime extensions, real notification delivery and CDN reachability. Render's ephemeral SQLite can reset data/settings/logo/2FA on deploy; these fixes do not solve persistence. All admin users currently have equal authority; email/phone ownership is not OTP-verified; customer/API tokens remain raw in DB. Protect backups and consider a future token migration. No claim of exploitation or security certification is made.

No secret credentials or user database dumps are included. config.php holds starter placeholders and must be configured. Document-root guards are Apache rules and require equivalent configuration on Nginx/IIS. New private 2FA key file must remain outside the web root or be supplied through server environment securely.

## 2026-11-24 Starter-account choice
Owner-selected behavior: existing default control credentials work on a fresh database with salted hashes only, no setup command and no forced first-login change. An approved amber warning asks for immediate change; it disappears after saving new credentials. Next now stores the authoritative hashes in control_credentials in SQLite; PHP uses control_users. Normal changes and process restarts never fall back to the starter account. Database deletion/restoration or ephemeral deployment can reset state; persistent storage and backups are required. Known defaults are unsafe while exposed online before changing them. Earlier instructions requiring setup before first login are superseded. Account/MFA/session protections remain.

## Header live search
PHP now shows inline results after a 250ms typing pause, including single Arabic letters. Maximum eight active-product results, spaced rows, scroll bounded to the viewport, loading/empty/error states and Enter fallback to products. Previous requests are cancelled and stale responses ignored. Product names render as text, image schemes are restricted, slug links encoded, database queries parameterized, query length capped at 120 characters and endpoint quota 120 requests/minute/IP. Tested mobile dark/light, product links, rapid typing, clear/reopen/Escape, HTML payloads and invalid queries locally. Next was not changed in this release.
