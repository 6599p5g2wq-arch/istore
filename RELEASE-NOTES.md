# iStore PHP parity pass, 24 November 2026

This supersedes earlier release notes. The PHP source, MySQL starter schema/catalog, local compiled CSS, storefront, admin, separate control panel and mobile API are included. Read HOSTING-AR.md and PARITY-STATUS-AR.md. This is a tested local release, not a claim of literal 100% equivalence or a security certification.

Store changes: wrapped product-filter chips and hidden advanced filters, blur/theme icons/header entry, live search with spacing and stale-response protection, variant-gated cart and wishlist cards, product drag tilt and thumbnails, horizontal cart rows and separate summary, checkout cards/default city/coupon/secondary currency/points, debounced lead capture, account tabs and profile/order cards, private receipt access with phone gate, repaired five-state tracking, analytics/pixels and SEO/robots/sitemap/Next-path redirects.

Panel changes: mobile/desktop sidebar and live badges, category/brand cards and edit panels, product controls/dashboard stat layout, announcement effect preview, section ordering, image-picker upload previews, inline city editing and last-city guard, coupon cards/program switches, control logo upload/delete and text limits. Existing POST/auth/CSRF guards remain. Runtime navigation and some detailed controls still differ, as listed in the parity status.

Security/compatibility: mobile guest tracking now uses POST api/v1/orders.php?action=track with JSON code and phone. Old GET phone/code returns 405. Update mobile clients. Other mobile API extras remain. Uploaded raw SVG logos are still rejected; use PNG/JPG/WebP. No personal owner hash belongs on GitHub. /admin and /control are separate. A fresh database with unchanged default admin configuration returns 500 outside development by design; configure a non-default ADMIN_PASSWORD before exposing production. Never enable development in production to bypass this check.

Checkout notifications run after the response under PHP-FPM when fastcgi_finish_request is present. Other SAPIs use a bounded synchronous shutdown fallback. There is no durable queue, retry policy or delivery guarantee. Real email, Telegram and external analytics receipt were not tested.

Validation for this pass: Next production build, zero known npm audit production-dependency findings, PHP syntax checks, 56 storefront route/viewport/theme captures, 64 authenticated admin route/viewport checks, account registration/profile, receipt privacy, five tracking statuses, variants, category CRUD, city create/autosave/delete, coupon create/delete, four image pickers, control logo upload/delete, announcement preview, CSRF/origin/access checks, server repricing, duplicate-stock and invalid input checks, search stale-result and markup safety. These are scoped tests, not exhaustive coverage of every field/edge case. Test fixtures were local and synthetic. No real hosting deployment or Apache rewrite runtime was verified.

Deployment: import install.sql only into an empty DB. Back up existing DB/uploads/2FA key first. Retain config and private starter identity on upgrades. Configure site_url to the actual HTTPS origin before relying on canonical links and sitemap. Apache rewrite/deny rules need equivalent Nginx/IIS configuration. Delete installer/SQL from the hosted root after setup. Source checksums are in SHA256SUMS.txt in the ZIP.
